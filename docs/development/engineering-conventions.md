# 安全与工程底线

这里集中维护跨模块的必要约束。具体写法见[编码规范](coding-standards.md)，验证方式见[开发流程](workflows.md)。只检查与当前改动有关的部分，不要求每次逐项出报告。

## 范围与依赖

- 面向中小型项目，默认选择简单实现，不提前增加分片或高可用抽象。
- 只用 pnpm workspace 和根锁文件；依赖放在实际使用的应用或包内，变更须有实际用途，不引入第二套锁文件。
- 只改任务涉及的内容，保留已有的无关修改，清理本次改动产生的无用代码。

## 技术选型与现代实践

本原则适用于整个项目的代码风格、架构设计、依赖与工具选型、接口、测试和部署方案。

- 优先采用当前技术生态中主流、成熟、持续维护的风格与方案，避免在新代码中继续引入已弃用的 API、停止维护的依赖或已有成熟替代的过时做法。
- 涉及“最新版本”“当前推荐”“是否弃用”等判断时，先核对官方文档、发布说明和项目锁定版本；不凭记忆认定，也不直接把最新版示例套到旧版本依赖上。
- 新增依赖或升级时优先评估当前稳定版本或受支持的 LTS，兼顾安全、兼容性、生态支持和迁移成本；不默认采用预发布版本，也不因版本更新就自动升级或替换现有方案。
- 方案复杂度与中小型项目的实际需求匹配。优先复用已有能力和成熟组件，不为追随趋势引入微服务、分片、多层抽象或额外基础设施。
- 具体格式以 ESLint / Prettier 和[编码规范](coding-standards.md)为准。局部修改保持风格一致；现有实现明显过时、存在风险或与选定方案冲突时，说明依据、收益和迁移影响，确认范围后逐步调整，不扩成无关的全项目重写。

## 安全与隐私

- 各应用分别维护环境变量，服务端 `.env` 不得复制到前端。`VITE_*` / `EXPO_PUBLIC_*` 是公开客户端配置，不能存放密钥。
- `.env`、私钥和真实凭据不入库；示例只使用占位值。日志、异常响应、文档和报告同样不得泄露敏感内容。
- 提交内容与署名不包含个人真实信息、本机路径、主机信息、AI 署名或会话链接。身份配置见[Git 约定](git-commit.md)。
- 生产环境的跨域来源、代理信任和管理接口权限必须明确配置；不得通过放宽默认值绕过启动检查。
- 对外错误使用统一响应，未知错误隐藏内部实现细节；完整诊断信息留在经过脱敏的日志中。

## 分层与校验

- 服务端 Controller 处理路由、校验和响应；业务逻辑放 Service，数据访问放 Repository。
- 请求体、查询和路径参数通过 DTO（数据校验对象）与全局管道校验。服务不重复校验已保证的结构，但仍负责业务条件。
- 返回数据经过响应实体筛选，不直接暴露数据库整行。用户端不暴露内部数字主键；管理端需鉴权。
- 服务端环境变量在 `apps/server/src/configs/` 校验后使用，不由业务代码绕过配置层读取关键参数。
- 管理后台与手机端按[前端开发](frontends.md)组织组件、路由和状态；客户端校验、隐藏按钮或路由拦截只能改善交互，服务端仍须独立认证授权。共享包只承载公开契约和客户端能力，不导出 Nest、数据库或服务端配置。

## 文件写入与 Storage

**服务端应用运行时除日志外，禁止任何本地文件系统写入；文件与对象的写入统一通过 S3 兼容 Storage。** 该约束覆盖所有环境中的 API 进程、HTTP 请求、Worker、定时任务及其调用的第三方库，不仅禁止长期保存，也禁止先落盘再上传。

- 本地文件与目录的创建、覆盖、追加、移动和删除均在限制范围内，不能通过子进程或第三方库间接执行；只读访问已发布资源不受此限制。
- 上传、附件、图片处理、报表导出、归档及其他生成文件均以流或受限内存处理，需保存时直接写入 Storage。大文件不得整文件无界缓冲；同时限制大小、并发、耗时，并处理取消与失败清理。
- 不创建本地 `uploads/`、导出目录、文件缓存或临时文件，不写 `/tmp`、容器可写层、宿主机挂载目录；`tmpfs` / 内存文件系统也不能作为绕过约束的文件落地方式。不得借日志目录保存业务文件、附件或文件内容。
- Storage 不可用时明确失败或按业务策略重试，禁止回退到本地文件。依赖只能输出到本地路径时，先选择支持流 / 内存的实现；不能自行开放落盘例外。
- 文件的上传、读取、删除与 PUT 预签名统一经 Storage 能力处理；浏览器直传使用 Uploader 签发与核验，业务层不散落各服务商 SDK，也不提供 `local`、NAS 或其他非 S3 协议的业务存储驱动。仅封装当前需要的能力，不预建多后端框架。
- 结构化业务数据仍使用数据库，缓存与队列仍使用 Redis；这条约束不要求把它们改存 S3。数据库只保存必要的对象标识、归属、状态等元数据，不以本地路径作为文件定位方式。
- 凭据仅由配置层注入，业务文件默认私有；访问前校验归属与权限，不把长期凭据或带授权信息的地址写进日志。应用 Storage 与备份仓库使用独立权限和命名空间。
- 源码、迁移、翻译和随镜像发布的静态资源可在运行时只读使用，应用不得修改。源码编辑、依赖安装、构建产物与开发工具的隔离测试文件不属于业务运行时写入，不得用这些用途为业务落盘开口子。
- 日志是唯一的应用本地写入例外，仍受脱敏、目录与轮转限制；Docker 部署沿用 stdout / stderr 交给日志驱动收集，见[日志模块](../modules/logger.md)。

**独立备份与恢复属于另行授权的运维操作，不受应用运行时无落盘约束直接限制。** 经批准可使用专用运维目录暂存、恢复文件，按[备份与恢复](../backup-and-restore.md)管理权限与清理；不得在应用 / Worker 内嵌这类脚本，或把运维目录挂给应用作为上传、导出和缓存目录。开发构建、发布工具及数据库 / Redis 服务自身的数据写入同样不等于应用业务文件落盘，仍遵守各自的安全与授权要求。

脚手架通过按需导入的 [StorageModule](../modules/storage.md) 统一提供 `StorageService` 和 [UploaderService](../modules/storage.md#浏览器直传)，默认 `AppModule` 不装配，也未提供公开上传 Controller 或鉴权。直传链接短时有效并防止覆盖已有对象，不保证严格一次性；核验依据必须来自业务持久化的可信记录，不能信任客户端回传的 key、类型或长度。业务层负责归属授权、配额、文件安全检测、状态关联和资源限制；签名 URL 不进入日志，bucket CORS 由独立管理权限配置。

S3 对象不能当作可追加或原地修改的本地文件。存储失败、取消或直传返回 412 后须先确认结果，不能承诺原子回滚或盲目删除同名对象；分片清理和并发覆盖边界见模块文档。SeaweedFS 服务自己的数据卷不属于应用写入。测试不得写入真实对象存储，见[测试安全边界](testing.md#测试安全边界)。

手机本地偏好和安全凭据按[移动端规范](frontends.md#移动端本地数据与业务文件)独立管理；上传业务文件仍通过服务端授权与 S3 兼容 Storage，客户端不得持有长期 S3 凭据。移动端能力不构成服务端落盘的例外。

## 数据一致性

- 表结构和基础数据通过迁移维护，迁移文件随代码提交；seed 只负责开发演示数据。
- 仓储使用合法的 `id` 主键，并遵循 `deletedAt` 软删除约定。公开标识与分页规则见[数据库](database.md)和[接口规范](rest-api.md)。
- 唯一性用数据库约束保证；先查后写不能替代约束。多表写入按需使用同一事务，不隐瞒部分失败。
- 写操作考虑重试与重复请求；涉及资金时使用精确金额表示，补充并发和重复执行验证。
- 分布式锁不能替代事务、唯一约束或库存/余额的并发控制。

## Redis 与资源释放

- 只支持 `single`（单机）和 `sentinel`（哨兵），非法模式启动时报错，不静默回退。
- 缓存、锁、队列各自读取连接配置并使用不同 DB。独立 DB 只是键空间隔离，不能代替实例级持久化和淘汰策略配置。
- 业务代码不调用 `cache.flush()` 或 `FLUSHDB`；缓存不得与锁、队列等数据共用 DB。
- BullMQ 使用专用连接，连接的创建方负责关闭；不要把共享客户端直接交给 Worker。
- 初始化失败要释放已创建资源，停机避免重复关闭和悬空异步操作。模块的详细语义见[基础设施文档](infra-modules.md)。

## 测试与交付

- 测试只使用隔离的临时资源；禁止写入生产数据、调用外部真实写入接口或操作区块链主网，不加载生产凭据和主网私钥。无法确认目标与副作用时停止相关测试，完整约束见[测试安全边界](testing.md#测试安全边界)。
- 可自动复现的缺陷保留为回归测试，不通过跳过测试、恒真断言或降低门槛掩盖失败。
- 代码、示例、模板与使用说明同步更新。只声明实际执行过的验证。
- 提交内容保持单一主题；推送与合并遵循[Git 约定](git-commit.md)。AI 不自动提交、推送或代替人工批准。
