# 国际化模块

源码入口：[I18nModule](../../src/common/modules/i18n/i18n.module.ts)。模块封装 `nestjs-i18n`，提供全局翻译服务和请求语言解析；DTO 校验由应用层的 [I18nZodValidationPipe](../../src/app/pipes/i18n-zod-validation.pipe.ts) 负责。

## 注册与翻译

[AppModule](../../src/app/app.module.ts) 已导入一次 `I18nModule`，底层模块全局提供 `I18nService`，业务模块无需重复导入。

```typescript
import { Controller, Get } from '@nestjs/common';
import { I18nContext, I18nService } from 'nestjs-i18n';

@Controller('hello')
export class HelloController {
  constructor(private readonly _i18n: I18nService) {}

  @Get()
  hello() {
    const text = this._i18n.t('common.hello', {
      lang: I18nContext.current()?.lang,
    });
    return { data: { text } };
  }
}
```

无请求上下文时可显式传入 `lang`，未传则使用模块的回退语言。翻译模板包含占位符时，通过 `args` 传入插值参数。

## 语言与资源配置

语言按以下顺序解析，先得到语言的解析器生效：

1. Query 参数 `?lang=zh-CN`。
2. `Accept-Language` 请求头。
3. `x-lang` 自定义请求头。
4. `I18N_FALLBACK_LANGUAGE`，默认 `en`，配置见 [i18n.config.ts](../../src/configs/i18n.config.ts)。

模块将 `zh` / `zh-*` 映射到 `zh-cn`，因此 `zh-CN` 可使用现有中文资源。当前资源位于 [src/i18n](../../src/i18n)：

```text
src/i18n/
├── en/
│   ├── common.json
│   ├── validation.json
│   └── error.json
└── zh-cn/
    ├── common.json
    ├── validation.json
    └── error.json
```

每个 JSON 文件构成一个命名空间，通过 `namespace.key` 访问翻译值。翻译路径固定为源码中的 `src/i18n`、编译产物中的 `dist/i18n`，不提供路径环境变量；修改目录时必须同步模块路径与 [nest-cli.json](../../nest-cli.json) 的资源复制规则。

仅 `NODE_ENV=development` 开启翻译文件监听和模块日志。非开发环境配置 `throwOnMissingKey: true`，普通翻译调用可能因缺键抛错；业务代码应补齐翻译，不要依赖开发环境返回原始 key 的行为。开发资源监听与构建说明见 [架构说明](../development/architecture.md)。

## DTO 校验文案

请求 DTO 使用 [createZodDto](../../src/common/utils/zod/create-zod-dto.ts)，应用层通过 `APP_PIPE` 全局注册 `I18nZodValidationPipe`。本模块不再配置 `I18nValidationPipe` 或 `I18nValidationExceptionFilter`。

校验失败抛出 [ZodValidationException](../../src/app/exceptions/zod-validation.exception.ts)，响应为 HTTP 422；完整响应结构见 [REST API](../development/rest-api.md#校验与本地化)。`errors[].message` 是可直接展示的用户文案，`field` / `code` / `params` 保持机器可读。

文案优先级从高到低：

1. schema 显式指定的 `message`。
2. 请求语言对应的 `validation.json` 模板与字段名。
3. zod 官方 locale 兜底：中文使用 `zhCN`，其他情况默认英文。

目录模板按以下次序查找：必填字段缺失时先找 `required`，再找 `<code>_<origin>`（如 `too_small_string`）、`<code>`、`default`。模板支持 `{field}`、`{minimum}`、`{values}` 等约束参数；原始输入不参与文案插值。

`fields` 中的字段名称先匹配完整路径，再匹配叶子字段名，最后回退原始路径。校验管道会将翻译缺键（包括非开发环境的缺键异常）视为未命中，继续寻找模板或 locale 兜底。

新增对外字段或校验规则时，同步维护 [英文校验文案](../../src/i18n/en/validation.json) 和 [中文校验文案](../../src/i18n/zh-cn/validation.json)，已有行为见 [管道单元测试](../../src/app/pipes/__tests__/i18n-zod-validation.pipe.unit-spec.ts)。

## 类型提示与扩展

[nestjs-i18n.d.ts](../../src/common/modules/i18n/types/nestjs-i18n.d.ts) 已包含基于英文资源的 `I18nTranslations` 映射和 `I18nService` / `I18nContext` 扩展声明。但当前 [tsconfig.json](../../tsconfig.json) 未开启 `resolveJsonModule`；使用这些 JSON 类型导入来约束翻译键前，需要完善相应配置并验证类型检查，不能仅凭这份声明认定已具备严格的键检查。

新增命名空间时同步增加声明中的资源类型，例如现有映射：

```typescript
type I18nTranslations = {
  common: typeof import('@/i18n/en/common.json');
  validation: typeof import('@/i18n/en/validation.json');
  error: typeof import('@/i18n/en/error.json');
};
```

新增语言时补齐相同命名空间，按需要调整模块的 `fallbacks`；如需该语言的 zod locale 兜底，同时更新管道的 `resolveLocaleError()` 并补测试。类型提示不能保证所有语言的资源内容完整。
