# 工程约定（通用不变量）

> **审查与实现的成文基线**：第 0 档循环 review、第 3 档代码审核时，以本文为「逐条断言有没有违反」的清单，而不是每次从零重新发现同一批坑。
>
> - **怎么写代码**（命名、函数长度、RO-RO 等）→ [coding-standards.md](coding-standards.md)
> - **怎么验收**（四档流程、PR 四件产物）→ [task-acceptance.md](task-acceptance.md)
> - **怎么分层 / 建表 / 写接口 / 测** → 各专题 reference（下文「详见」）
>
> 本文只收**不可违反的工程不变量**。业务项目若增加资金/链上/支付等领域规则，在本文「业务域扩展」追加，不得削弱本脚手架底线。

## 1. 安全、隐私与密钥

| # | 不变量 | 说明 |
|---|--------|------|
| S1 | **密钥与凭证不入库** | `.env` 只保留 example；供应商 key、密码、token、私钥内容禁止进 git、日志明文、注释、PR、验收报告 |
| S2 | **本机/个人信息不入库** | 真实姓名、个人邮箱、本机用户名、绝对路径、主机名等禁止出现在代码/文档/提交/PR（见仓库根 CLAUDE.md 规则 A） |
| S3 | **AI 署名不入库** | 禁止 `Co-Authored-By: Claude`、会话链接、`Generated with …` 等 |
| S4 | **对外错误不泄露内部细节** | 未知异常 → 统一 500 信封；公开标识碰撞等分配失败 → 不透明错误（见 [database.md](database.md)）；日志可记细节，响应不给攻击面 |
| S5 | **信任边界默认收紧** | `APP_TRUST_PROXY` 默认 false；生产 CORS 过松只 warn 不静默当安全；管理端暴露 bigint `id` 的路由必须视为需鉴权面 |

## 2. 配置与环境

| # | 不变量 | 说明 |
|---|--------|------|
| C1 | **配置经 zod 校验** | 环境变量在 `src/configs/*.config.ts` 声明 schema，经 `registerEnvAsConfig` 注册；禁止业务代码直接读未校验的 `process.env` 拼关键路径 |
| C2 | **模块 Redis 配置自洽** | Cache / Lock / Queue 各自读自己的 `*_REDIS_*`；可引用 `${REDIS_*}` 锚点，但**禁止多模块共用同一 Redis DB**（可清空的缓存 vs 不可丢的锁/队列） |
| C3 | **Cluster 模式禁止乱设 DB** | Redis cluster 下显式 `*_REDIS_DB` 必须启动失败（fail-fast），不得静默忽略 |

详见 [env-vars.md](env-vars.md)、[infra-modules.md](infra-modules.md)。

## 3. 数据与持久化

| # | 不变量 | 说明 |
|---|--------|------|
| D1 | **表必须有合法 `id` 主键** | bigint + `createPrimaryKeyColumn()`；否则 `BaseRepository` 启动抛错 |
| D2 | **结构变更走 migration** | 开发与生产同一套迁移；`db:generate:* --name=<kebab>` 必带 name；**禁止**把 `drizzle-kit push` 当日常流程 |
| D3 | **软删除约定** | 有 `deletedAt` 即自动软删；查询默认过滤已删行；删除 API 不得绕过该约定却装作软删 |
| D4 | **公开标识分长短、策略分岔；列名随业务语义** | 长码直插、短码先查空；列名用业务含义（如 `accessKey`/`inviteCode`），`publicId`/`shortPublicId` 仅为 demo 泛化名；**禁止**缩短长码冒充推荐码，也禁止短码当 URL 资源 id |
| D5 | **唯一冲突语义分明** | DB 唯一冲突 → `RecordAlreadyExistsException`（409）；公开标识分配失败不得伪装成「记录已存在」给用户；业务唯一键（如 name）仍应 409 |
| D6 | **基础数据进数据迁移** | 必备初始数据用 `--custom` 数据迁移；seed 仅开发演示，不承担生产基线 |
| D7 | **事务边界清晰** | 多表一致性写操作走 `db.transaction`，仓储方法接收 `db`/`tx`；禁止「一半成功一半失败」却无补偿约定 |

详见 [database.md](database.md)。

## 4. 分层与 API

| # | 不变量 | 说明 |
|---|--------|------|
| A1 | **控制器无业务 / 无直访仓储** | Controller：校验入参 → 调 Service → 组装响应；禁止拼 SQL、堆业务分支 |
| A2 | **响应必须经 Entity 净化** | 返回前 `Entity.create(row)`（或等价 zod DTO）；禁止把 Drizzle 原始行直接甩给客户端 |
| A3 | **路径参数必须走 Param DTO** | 禁止裸 `@Param('id')`；用户端资源定位用长码列（列名随业务语义），管理端才可暴露 `id` |
| A4 | **统一错误信封** | 非 2xx 走全局过滤器形状；业务勿自造另一套错误 JSON |
| A5 | **入参校验在边界完成** | 请求体/查询/路径用 zod DTO + 全局管道；服务层不重复「防呆式」校验已保证的形状（业务规则校验除外） |
| A6 | **游标对外必须加密** | 列表 `nextCursor` 用 `APP_MASTER_KEY` 做 AES-256-GCM（key 固定 32 字节，env 为 64 位 hex，生成 `openssl rand -hex 32`）；筛选在 URL；payload 含 scope + 多列 keyset；勿把裸 `id` 当 cursor |

详见 [rest-api.md](rest-api.md)、[module-development.md](module-development.md)。

## 5. Redis、缓存、锁、队列

| # | 不变量 | 说明 |
|---|--------|------|
| R1 | **缓存可丢，锁/队列不可与缓存共 DB** | `CACHE_REDIS_DB` 独立；锁与队列各自独立 DB 或独立实例 |
| R2 | **禁止业务调用 `cache.flush()` / `flushdb`** | 会清空整库；cluster 下 flush 应拒绝 |
| R3 | **分布式锁不替代 DB 约束** | 余额/库存等必须事务 + 行锁/乐观锁/唯一约束；锁只做跨实例互斥 |
| R4 | **BullMQ 使用独立连接** | 不把共享 ioredis client 直接塞给 Worker；经 `QueueModule` / 约定工厂 |

详见 [infra-modules.md](infra-modules.md)。

## 6. 幂等、并发与状态（脚手架底线 + 业务扩展位）

| # | 不变量 | 说明 |
|---|--------|------|
| I1 | **写路径考虑重放** | 客户端重试可能导致重复创建时，用唯一约束 / 幂等键挡住；失败响应可区分「已存在」与「分配失败」 |
| I2 | **并发以 DB 为真相** | 先查后写存在 TOCTOU（查后改前被别人改）时，以唯一约束或事务内条件更新兜底；短码「查空再插」承认竞态并转不透明错误 |
| I3 | **状态迁移显式** | 若引入状态机字段，非法迁移必须拒绝并有测试；禁止「静默改成任意状态」 |
| I4 | **（业务扩展）资金与账务** | 金额用整数最小单位（如 bigint/分），禁止 IEEE 浮点累加；入账/扣款路径幂等；外部回执（receipt）状态必检后再推进本地状态——业务项目写入本表扩展区 |

## 7. 日志与可观测性

| # | 不变量 | 说明 |
|---|--------|------|
| L1 | **`msg` 中文 + `event` 英文枚举** | 结构化字段便于检索；禁止把密钥、完整证件号、支付敏感原文打进日志 |
| L2 | **预期内失败与意外失败分级** | 业务冲突可用 warn/info；未处理异常走 error 并由过滤器收口 |
| L3 | **平滑停机可预期** | 进程信号用 `process.once`；停机超时有兜底；禁止重复注册导致多次 shutdown |

## 8. 测试与 CI

| # | 不变量 | 说明 |
|---|--------|------|
| T1 | **能自动化的必须进 `pnpm test` / CI** | 一次性手工检查不能替代回归 |
| T2 | **断言必须能红** | 禁止无断言、恒真断言、无故 skip；失败路径要有会变红的用例 |
| T3 | **推送前本地门禁全绿** | `pnpm lint && pnpm build && pnpm test`（涉及 e2e 加 `pnpm test:e2e`） |
| T4 | **测前有覆盖清单** | 有风险改动：正常 / 边界 / 失败 / 幂等 / 并发按需枚举；缺口显式写明不测理由（见 [task-acceptance.md](task-acceptance.md)） |

详见 [testing.md](testing.md)。

## 9. Git 与交付

| # | 不变量 | 说明 |
|---|--------|------|
| G1 | **`main` 禁直推** | 短命分支 + PR + Squash merge；CI `ci`/`docker` 全绿 |
| G2 | **远程用 SSH** | `git@github.com:<owner>/<repo>.git`；署名 noreply，无个人真实邮箱 |
| G3 | **原子提交 + 文档同发** | 一次一事；迁移/模板/验收报告随代码，不留「稍后补」 |
| G4 | **有风险 PR 含四件产物** | review 记录 / 测试清单与覆盖对照 / 人工取证 / 审核导读；缺则退回 |
| G5 | **不自动提交** | 验收报告出完后询问用户是否提交 |

详见 [git-commit.md](git-commit.md)、CLAUDE.md 规则 A / 6。

## 10. 依赖与范围

| # | 不变量 | 说明 |
|---|--------|------|
| P1 | **包管理只用 pnpm** | 禁止 npm/yarn 引入锁文件分叉 |
| P2 | **禁止随手加依赖** | 新依赖须有明确理由；能用标准库 / 已有模块解决的不新增 |
| P3 | **不越里程碑边界** | 对照计划「明确不做」；提前做的要么删要么回写规格 |
| P4 | **外科手术式改动** | 不顺手重构无关代码；本次产生的孤儿 import/死代码要清 |
