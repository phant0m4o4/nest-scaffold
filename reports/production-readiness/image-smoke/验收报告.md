# 生产镜像验证

本文记录生产镜像专项验收时点；正文中的“未提交”和范围限制均指该阶段。后续用户已授权修复 Redis Cluster 缓存批量操作并整理本地提交，相关专项证据见 [Redis Cluster 验收报告](../redis-cluster/验收报告.md)，最终汇总见文末。

## 范围与测前清单

仅验证本仓库 Dockerfile 的生产镜像，不连接本机业务数据库，不读取本机 `.env`，不部署、不提交。

- 正常：完整生产入口启动、真实 MySQL / Redis 连接、非 root 身份、Argon2 原生依赖、翻译与迁移资源、HTTP 错误信封和请求标识。
- 边界：生产不暴露示例和队列管理页面；跨域白名单允许、非白名单拒绝授权。
- 失败：生产跨域来源为空或 `*` 且携带凭证时，启动失败。
- 幂等：镜像内执行迁移两次，迁移记录与基础数据不重复。
- 时序：真实 SIGTERM 发送到 PID 1，验证退出码、数据库与 Redis 释放日志。
- 明确不测：Redis Cluster、队列任务消费、PostgreSQL、业务 CRUD（生产当前未开放业务路由）；不宣称本次覆盖这些能力。

## 第 0 档：审查记录

1. 生产依赖视角：发现迁移配置直接导入 `dotenv/config`，但项目未声明直接依赖。最终镜像中直接运行迁移命令复现 `Cannot find module 'dotenv/config'`。命令行包装器可能因 `NODE_PATH` 暂时掩盖该问题。
2. 边界视角：当前生产没有健康检查或业务路由，不应以虚构的 `/health` 200 为标准；通过 HTTP 404、跨域预检和基础设施启动日志联合验证。

3. 依赖修复：显式声明 `dotenv` 生产依赖，锁定到已有的 17.4.1；容器迁移命令改为直接运行镜像内的 drizzle-kit，不依赖命令包装器或运行时下载。旧镜像测试结果为 10 通过、1 失败，失败正是迁移缺少 dotenv；重建后 11 项全部通过。
4. 异常时序视角：发现测试总启动时限 600 秒短于构建、依赖、应用各阶段预算之和 660 秒，可能提前触发清理；将总时限提高到 900 秒。依赖启动使用 `Promise.allSettled`，等待双方结束后才处理失败。
5. 修复后安全与失败路径复核：零新增具体缺陷。临时容器位于独立网络；缓存、锁、队列配置各用独立 Redis DB；无本机环境文件或目录挂载。清理使用持有的容器对象和随机镜像标签；指定的预构建镜像不删除。库在等待启动失败时也会移除容器与匿名卷。
6. 最终正确性自查：零新增具体缺陷。资源用例实际解析六份翻译 JSON；迁移用例检查最终记录和基础数据；停机断言包含退出码及连接释放日志。测试不替换应用内部组件，持续集成镜像标签与复用变量一致。

本次对工程约定的核对：安全、配置隔离、迁移、错误信封、停机、测试、范围约束均遵守；无表结构、业务事务、资金逻辑或 Redis Cluster 算法改动。工作区原有修改保留；无提交、推送或人工审批。
