# Redis Cluster 缓存批量操作修复

## 范围与测前清单

提交整理时复核发现：把多键命令拆成单键后放入同一个手动 pipeline（一次发送多条命令），仍不能跨 Redis Cluster 主节点。用户确认先修复、补真实集群回归，再按主题提交。

- 正常：`getBatch`、`setBatch`、`deleteBatch`、`existsBatch` 的键分别落在三个真实主节点。
- 边界：输入顺序、重复键、未命中、TTL 120 秒和永久值、空数组、TTL 为 0。
- 失败：损坏 JSON、Redis WRONGTYPE（键的类型不符合命令要求）、单项命令失败。
- 预校验：后续项的键为空、值为 undefined、循环引用时，不提前写入前项。
- 重放与计数：重复删除只计算实际删除次数；存在性检查保留 Redis 对重复键的逐项计数。
- 明确不测：集群故障转移、重分片、锁租约、队列消费；不保证跨键原子性，也不宣称本次覆盖这些能力。

## 第 0 档：审查记录

1. 客户端真实语义审查：已安装的 ioredis 文档和 `Pipeline.js` 均明确手动 pipeline 的所有键必须属于同一节点分配组。原来的模拟 pipeline 无法捕获跨主节点错误。
2. 在旧实现上运行三个独立 Redis 8 主节点：11 项中 6 项失败、5 项通过。失败均为 `All keys in the pipeline should belong to the same slots allocation group`；读取、写入两种 TTL、删除和存在性检查均复现。
3. 修复：Cluster 分支并发发送单键命令，由客户端逐键路由，使用 `Promise.allSettled` 等待全批完成。单机分支保留 MGET / DEL / EXISTS 与写入 pipeline。
4. 异常时序自查：先校验并序列化所有写入项，再发出命令；保留逐项读取失败、写入成功计数、删除及存在性检查抛错的契约。命令一旦发送，仍可能部分成功，文档明确不承诺跨键原子性。
5. 独立复核：零新增具体缺陷。核对顺序、错误传播、重复项计数、预校验及资源所有权；真实测试的键通过 CLUSTER SLOTS 和 KEYSLOT 确认分属三个主节点，而非只测试同节点不同槽。
6. 全量并行执行暴露集群准备时序问题：集群创建命令结束不等于所有节点已报告就绪。测试补充三个节点 `cluster_state:ok` 的显式等待（30 秒上限），并保留有限连接重试；修复后独立复跑 11 项通过，类型和代码规范检查通过。

安全、配置隔离、错误处理、测试和最小修改范围均遵守项目约定；无数据库或资金逻辑改动。真实集群全部为测试创建的独立容器和网络，不读取本机 `.env`，不执行全局清理。
